# UI改进计划

## 频谱

1. 去除"频谱 · 50 Hz → 8 kHz ───────────────────────────────────────────────────────────────"这一整段元素. 理由: 保持界面简洁, 没有必要加入.
2. 取该范围所有的FFT bin 的 max dB, 把响应曲线 gamma 从 1.6 降到大约 0.7~0.8, Attack->0.85, Decay->0.28 理由: 增大频谱音频相应灵敏度, 提升打击感
3. 修改dB映射, -72 dB->0, -12dB->1. 理由: 增加起伏敢, 安静的时候能压下去, 鼓点能够冲起来

## 歌曲展示

- 主要目标: 防止过长的元素侵占显示位置, 防止过短的元素浪费空间

1. 给每一列定义优先级:
- 标题：最高
- 歌手：高
- 专辑：中
- 格式：低
- 时长：固定保留
2. 做一个按终端显示宽度截断字符串的函数
- 超长就变成 xxxxx…
- 不要直接按 Rust 字符串长度算，最好用 unicode-width
- 中文要按实际终端宽度处理
3. 根据当前可用宽度动态分配列
- 宽：标题 + 歌手 + 专辑 + 格式 + 时长
- 中：隐藏格式
- 再窄：隐藏专辑
- 很窄：只留标题 + 时长
4. 保证一首歌永远只占一行
- 不换行
- 不让长标题把后面内容挤出去
- 每个可变字段都必须经过截断

理由: 优化长歌名, 长歌手名歌曲的显示占用, 美化歌曲栏目

## 播放进度

- 主要目标: 简化与可视化优化

1. 把文字挪到进度条两侧, 按照当前进度/进度条/总时长拆开展示
2. 进度条换成纯ASCII样式

效果概览:
" 01:28 ============>---------- 03:27 "
超过一小时自然拓展
