# 重扫选择恢复与扫描说明修正计划

状态：已实施并通过自动验证，等待人工验收
范围：完善 GLM 生成的未提交改动，不扩展软链接扫描或播放失败架构

## 1. 目标

完成以下三个已确认事项：

1. 重新扫描后，即使当前保留着非空模糊搜索查询，也能在异步匹配完成后按路径恢复原来选中的歌曲。
2. 保留“播放异步报错时尝试下一首”的小幅改进，但准确描述它的能力，不宣称已经彻底解决所有坏文件循环。
3. 把 README 的符号链接限制改成更精确的“音乐库目录内部的符号链接”。

## 2. 用户决定

- 模糊搜索依赖 Nucleo 的异步行为保持不变，修正应用对异步结果的接入方式。
- 坏文件连续异步失败属于低概率、中等影响问题；本轮接受部分改善，完整失败计数以后再做。
- 当前不支持文件软链接，只在 README 中准确说明限制。
- 可以调整 README 和 Changelog 的少量措辞。

## 3. 已确认的技术事实

- `SearchIndex::replace_tracks()` 会清除旧结果；查询非空时，新结果由 Nucleo 后台计算，不能立即用于恢复选择。
- Nucleo 的 `Status::running` 能说明当前匹配是否仍在后台进行。
- `App::selected` 表示“可见搜索结果中的位置”，不是 `tracks` 的原始索引，因此必须等新搜索快照稳定后再恢复。
- 当前 `play_next(false)` 只会让单曲循环尝试后续歌曲；只有一首坏歌或所有歌曲都异步失败时，仍可能循环。

## 4. 实施方案

### 4.1 让搜索层保留运行状态

修改 `src/search.rs`：

- 在 `SearchIndex` 内保存最近一次 Nucleo `Status::running`。
- `tick()` 和 `reparse()` 每次调用 matcher 后都同步该状态。
- 新增仅供 crate 内部使用的 `is_running()`，不改变现有公共 `tick() -> bool` 接口。

这样应用可以知道“结果已经稳定”，同时不阻塞 UI 等待模糊搜索完成，也不改变 Nucleo 的后台工作方式。

### 4.2 延迟恢复选中歌曲

修改 `src/app.rs`：

- 在 `App` 中增加一个仅存在于内存的 `pending_selected_path: Option<PathBuf>`。
- 扫描完成时，在替换曲目之前保存当前选中歌曲路径。
- 替换曲目和搜索索引后，把该路径标记为“等待恢复”，不立即假设可见结果已经就绪。
- 每次正常 `search.tick()` 后：
  - matcher 仍在运行：继续等待；
  - matcher 已停止：在新曲目中按路径找到原始索引，再在可见结果中找到位置；
  - 找不到歌曲或歌曲不匹配当前查询：回到第一项；
  - 完成后清除待恢复路径。
- 用户在等待期间主动移动选择、编辑或清除查询时，取消待恢复路径，避免后台结果随后覆盖用户的新操作。

正在播放歌曲的 `playing_index` 仍按现有路径逻辑立即恢复，不受这一延迟选择机制影响。

### 4.3 收敛坏文件改动的承诺

保留 GLM 已加入的 `PlayerEvent::Error => play_next(false)`，但：

- 把代码注释改为“播放错误不是自然结束，单曲循环应先尝试后续歌曲”，不再声称已经杜绝死循环。
- 把 Changelog 改为“减少单曲循环反复重试同一坏文件的情况”。
- 本轮不新增失败路径集合、连续失败计数或持久坏文件状态。

### 4.4 修正文档

修改 `README.md`：

> 扫描不会跟随音乐库目录内部的符号链接：目录软链接会被跳过以避免循环，指向音频文件的软链接目前也不会被收录。

不修改 `src/library.rs` 的扫描行为。

## 5. 测试

### 5.1 搜索层

- 查询非空并替换曲目后，`is_running()` 最终回到 `false`。
- matcher 完成时结果 snapshot 与当前查询一致。

### 5.2 应用层

- 查询为空时，重扫后按路径恢复选中歌曲。
- 查询非空时，等待 Nucleo 完成后仍恢复到同一路径对应的可见结果。
- 原歌曲消失或不再匹配查询时回到第一项。
- 用户在等待恢复期间更改查询或移动选择时，旧的待恢复路径不会覆盖用户操作。
- 保留现有播放模式测试，确认 `RepeatOne + natural_end=true` 重播当前歌曲，而 `natural_end=false` 尝试下一首。

测试异步 matcher 时使用明确截止时间，避免测试永久等待。

## 7. 验收标准

1. 保留搜索查询后重新扫描，光标仍能回到原来选中的歌曲。
2. 新搜索结果尚未完成时不会错误地把恢复操作判定为失败。
3. 用户的新导航或搜索输入优先于后台待恢复操作。
4. 查询为空、歌曲消失和正在播放索引恢复等原有行为不退化。
5. README 和 Changelog 不再作过度概括或绝对承诺。
6. 不新增依赖、配置字段或持久数据。

## 8. 明确推迟

- 遍历目录软链接及目录循环检测。
- 跨异步播放错误维护失败路径集合。
- 所有歌曲失败后的完整停止策略。
- 将 GStreamer Discoverer 改成可取消的异步架构。
