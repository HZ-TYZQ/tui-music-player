# MusicPlayer 0.3.0 音频可视化实施计划

状态：实施完成；自动验证与用户人工验收均已通过
建议目标版本：`music-player 0.3.0`
目标平台：Fedora 44 x86_64

## 1. 目标

为当前正在播放的歌曲增加终端内音频频谱。频谱直接分析 MusicPlayer 自己的 GStreamer 音频流，并在曲目列表下方固定显示，不采集其他应用的系统声音，也不启动 CAVA 子进程。

完成后，程序应当：

- 在曲目列表与“正在播放”区域之间显示一块带分隔线的频谱区域。
- 使用从低频到高频、由左到右排列的单排柱状图。
- 默认开启频谱；按 `v` 可以即时显示或隐藏。
- 记住用户上次的开关状态，下次启动时恢复。
- 在没有播放、暂停、切歌和终端缩放时保持稳定，不影响音频播放控制。
- 不增加新的 Rust crate、外部进程或 RPM 运行依赖。

## 2. 用户已经决定的事项

1. 选择 GStreamer `spectrum`，不使用 CAVA。
2. 频谱固定放在曲目列表下方，并增加清晰的分隔线。
3. 使用单排柱状图，频率从左侧低频逐渐过渡到右侧高频。
4. 频谱默认开启。
5. 使用 `v` 键切换显示和隐藏。
6. 将开关状态保存到配置文件，下次启动时恢复。
7. 播放图标采用“按钮下一步操作”语义：正在播放时显示暂停图标 `⏸`，暂停时显示继续图标 `▶`。

## 3. 由助手补充的技术方案

### 3.1 音频分析数据流

在 `src/player.rs` 中创建 GStreamer `spectrum` 元素，并把它设置为现有播放管线的 `audio-filter`：

```text
当前歌曲
  -> GStreamer 解码
  -> spectrum 分析（音频仍原样通过）
  -> 音频输出
           \
            -> 频谱消息 -> PlayerEvent -> App -> Ratatui 绘制
```

`spectrum` 只计算频段强度，不会替换或录制音频。播放器线程收到 GStreamer 消息后，仅把普通数值数组发送给应用主循环；界面层不直接持有 GStreamer 对象，以保持现有模块边界。

初始参数采用：

- 512 个线性分析频段，为 50 Hz 附近提供足够的基础分辨率。
- 50 毫秒分析间隔，目标约 20 帧/秒。
- 强度下限 `-60 dB`，低于该值按静音处理。
- 只读取 magnitude（强度），不读取 phase（相位），并将多声道合并分析。

这些是内部性能参数，不写入用户配置；如实机测试显示 CPU 使用率或视觉稳定性不理想，可在不改变产品行为的前提下微调并记录结果。

### 3.2 频谱状态与动画

在应用状态中保存当前一帧归一化后的柱高。处理规则：

- 将 `-60..0 dB` 映射为 `0..1` 的可绘制高度。
- 根据每首歌实际协商的采样率截取 50–8000 Hz，并对数映射为 32 根可见柱；采样率不足 16 kHz 时，上限自动收缩到奈奎斯特频率。
- 新数据上升时快速响应，下降时平滑衰减，减少柱条闪烁。
- 暂停、停止、播放结束或发生错误时，柱条逐渐回落到零，而不是冻结在最后一帧。
- 切换歌曲时清空旧数据，避免短暂显示上一首歌的频谱。
- 频谱隐藏时停止界面动画更新；GStreamer 分析元素仍留在管线中，避免运行时重建播放管线造成爆音或中断。若 API 允许安全切换，则同步关闭消息发布以减少无用事件。

主事件轮询从当前 100 毫秒调整为 50 毫秒，使动画能跟上分析消息。无播放时这只是轻量终端轮询，不会启动额外工作线程。

### 3.3 终端界面

在 `src/ui.rs` 中把主布局调整为：

```text
┌ 曲目列表 ─────────────────────────┐
│                                  │
└──────────────────────────────────┘
────────────── 频谱 ────────────────  <- 分隔线
▁▂▃▅▇█▆▄▃▂▁ ...                       <- 低频到高频
┌ 正在播放 ─────────────────────────┐
│ 曲名 / 模式 / 音量 / 队列          │
│ 播放进度                           │
└──────────────────────────────────┘
快捷键提示
```

具体绘制规则：

- 频谱开启时预留 5 行：1 行带“频谱”标题的分隔线，4 行柱状图。
- 使用 Unicode 八级方块字符形成细腻柱高，并沿用当前青色/品红色主题。
- 正常宽度最多显示 32 根柱，并在相邻柱之间留一个字符；窄终端自动减少显示柱数。
- 终端高度不足时优先保留曲目列表与播放状态；频谱自动缩为更少行，极窄时暂时不绘制，但不改写用户的开关设置。
- 频谱关闭时完全释放这 5 行给曲目列表。
- 页脚和 `?` 帮助弹层加入 `v` 的说明。

### 3.4 配置兼容性

在 `AppConfig` 中增加：

```toml
visualizer_enabled = true
```

配置结构已经使用 `#[serde(default)]`，因此旧配置缺少该字段时会自动采用 `true`。这是向后兼容的字段扩展，保留现有配置格式版本 `1`，避免用户已有配置被判为不支持。退出时与音量、静音一起原子保存。

### 3.5 依赖与 RPM

- 不新增 Rust crate。
- 不依赖 `cava` 可执行文件。
- GStreamer `spectrum` 属于 `gst-plugins-good`；当前 RPM 已经声明 `Requires: gstreamer1-plugins-good`，因此不新增 RPM 运行依赖。
- 播放器启动时若系统意外缺少 `spectrum` 元素，应返回包含缺失组件名称的明确错误，而不是崩溃。

## 5. 实施顺序

1. 为配置增加可视化开关及兼容性测试。
2. 在播放后端接入 `spectrum`，把消息转换成内部频谱事件。
3. 在应用层实现频谱状态、平滑衰减、`v` 开关与保存。
4. 在界面层实现分隔线、柱状图、动态尺寸和帮助文字。
5. 更新版本、README、man page、changelog 和 RPM spec。
6. 运行格式化、静态检查、单元测试和 RPM 构建。
7. 在真实终端中用实际音频做人工检查，并进行只读代码审查；发现问题后修正并复验。

## 6. 验证标准

自动化验证至少覆盖：

- 旧配置没有新字段时默认开启，保存后可正确恢复开关状态。
- `v` 只在普通界面切换频谱，不干扰搜索输入和弹层按键处理。
- dB 数值归一化会正确处理下限、上限、空帧和异常数值。
- 平滑和暂停/停止衰减不会越界。
- 不同终端宽度的频段重采样结果数量正确。
- 频谱开启和关闭两种布局在最小支持尺寸下都不会越界或崩溃。
- 缺少 `spectrum` 元素时给出可理解错误。

实施完成后运行：

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features
./packaging/build-rpm.sh
rpm -qpi packaging/rpmbuild/RPMS/x86_64/music-player-0.3.0-3.fc44.x86_64.rpm
rpm -qlp packaging/rpmbuild/RPMS/x86_64/music-player-0.3.0-3.fc44.x86_64.rpm
```

人工检查至少确认：

- 实际播放时柱条与音乐变化同步，声音没有中断或明显爆音。
- 暂停后柱条自然回落，继续播放后恢复。
- 切歌后不会残留上一首歌的频谱。
- `v` 隐藏后曲目列表立即获得额外空间，重启后保持上次选择。
- 缩放终端、打开帮助/播放列表和搜索时界面正常。

## 7. 助手采用的假设

1. 这项明显的用户功能作为次版本发布，版本号采用 `0.3.0`，而不是补丁版本 `0.2.1`。
2. “单排柱状图”指一组由左到右排列的垂直柱，每根柱可占多行高度，不是只有一行字符高。
3. 暂停或停止时采用平滑回落到零，这是比冻结最后画面更自然的默认行为。
4. 频谱颜色沿用当前界面主题，不增加颜色配置。
5. 本功能只可视化当前播放音频，不提供麦克风或全系统声音采集。

如这些假设与预期不同，应在批准计划前指出。

## 8. 本次暂不包含

- CAVA 子进程或 CAVA 配置文件兼容。
- 全屏可视化模式和多种可视化样式切换。
- 用户自定义频段数、刷新率、颜色、平滑系数或高度。
- 波形、声道分离、峰值保持线、歌词联动和封面动画。
- 麦克风、系统混音或其他应用音频的可视化。
- Git 提交、推送、打标签和 GitHub Release；实现验收后再单独执行。

## 9. 实施结果

- 已按批准方案接入 GStreamer `spectrum`、应用层平滑动画、终端柱状图、`v` 开关和配置持久化。
- 根据实际试听反馈，将频段区间最大值改为中心频率插值，并加入温和的低频显示补偿与响应曲线，避免多个左侧柱子重复命中同一低频峰值而成片顶格。
- 已按用户验收反馈统一播放图标语义，曲目列表和正在播放区域都显示按下 `Space` 后将执行的操作。
- 根据用户首次视觉验收的反馈，将最终参数调整为：512 个底层频段、50–8000 Hz 对数映射、最多 32 根可见柱、50 毫秒分析和界面轮询间隔、`-60 dB` 下限。
- 没有新增 Rust crate 或 RPM 运行依赖。
- `cargo fmt --check`、严格 Clippy 和全部 32 项测试通过；其中集成测试使用实际生成的 WAV 确认收到 512 段频谱消息和正确采样率。
- Fedora 44 x86_64 RPM 构建和 RPM 内部 release 测试通过；根据两轮体验反馈修订后将 RPM Release 提升为 3，主包为 `music-player-0.3.0-3.fc44.x86_64.rpm`。
- 自动化环境无法代替用户的真实声卡、音乐文件和终端视觉体验，安装后的听感与视觉效果仍需人工验收。
