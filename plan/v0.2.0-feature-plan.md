# MusicPlayer 0.2.0 日常可用版实施计划

状态：实施完成；等待用户决定是否安装、提交和发布
目标版本：`music-player 0.2.0`
目标平台：Fedora 44 x86_64

## 1. 目标

把 0.1.0 的基础目录播放器升级为能够长期日常使用的本地音乐库播放器。此前讨论的用户功能全部属于 0.2.0 的发布条件，不再划分 P0、P1、P2。

完成后，程序应当：

- 默认打开用户的 XDG Music 目录，并允许配置一个主音乐库。
- 在后台增量扫描音乐库，不阻塞终端界面。
- 展示标题、歌手、专辑、格式、总时长和播放进度。
- 支持平滑暂停、跳转、音量和静音。
- 支持顺序播放、列表循环、单曲循环和随机播放。
- 支持实时模糊搜索、临时播放队列和持久命名播放列表。
- 按 XDG 规范保存配置、播放列表和可删除缓存。
- 提供完整命令行帮助、内置按键帮助、自动化测试、GitHub Actions 和 Fedora RPM。

## 2. 用户已经决定的事项

1. 0.2.0 的全部已讨论功能都是发布所必需的。
2. 播放后端从 `ffplay` 子进程迁移到 GStreamer。
3. 使用单一主音乐库。
4. 首次启动默认采用系统的 `XDG_MUSIC_DIR`，不硬编码 `~/Music`。
5. 命令行传入的目录仅覆盖当前运行，不修改主音乐库配置。
6. 后台扫描音乐库，并使用 SQLite 做增量元数据索引。
7. SQLite 只保存可重建缓存；播放列表和设置不依赖该缓存才能存在。
8. 提供临时队列和可保存的命名播放列表。
9. 立即播放另一首歌曲时保留手动队列；当前歌曲结束后优先消费队列。
10. 使用直接快捷键和 `?` 帮助界面，不增加命令面板。
11. 搜索采用实时模糊过滤，覆盖标题、歌手、专辑和相对路径。
12. 接受新增 `nucleo` 依赖实现后台、Unicode 友好的模糊搜索。
13. 每个命名播放列表保存为独立 JSON 文件。
14. 删除播放列表绝不删除音乐文件；不可用歌曲保留记录并在播放时跳过；同一路径不重复加入同一列表；名称冲突不静默覆盖。

## 3. 用户可先安装的 Fedora 开发包

当前机器已经安装所需 GStreamer 运行时插件，只缺少开发文件和 SQLite 开发包。执行：

```bash
sudo dnf install \
  gstreamer1-devel \
  gstreamer1-plugins-base-devel \
  gstreamer1-plugins-bad-free-devel \
  sqlite-devel
```

这些软件包分别提供：

- `pkgconfig(gstreamer-1.0)`：GStreamer 核心开发接口。
- `pkgconfig(gstreamer-audio-1.0)` 和 `pkgconfig(gstreamer-pbutils-1.0)`：音频与媒体发现接口。
- `pkgconfig(gstreamer-play-1.0)`：高级播放器接口。
- `pkgconfig(sqlite3)`：系统 SQLite 开发接口。

`nucleo`、`clap`、`serde` 等 Rust 库不使用 DNF 单独安装；实施时写入 `Cargo.toml`，由 Cargo 和 `Cargo.lock` 管理。

## 4. 由助手补充的技术方案

### 4.1 XDG 数据位置

程序使用系统 API 获取目录，并遵守用户的 XDG 环境变量：

- 音乐库默认值：`XDG_MUSIC_DIR`。
- 配置：`$XDG_CONFIG_HOME/tui-music-player/config.toml`。
- 播放列表：`$XDG_DATA_HOME/tui-music-player/playlists/*.json`。
- 音乐索引：`$XDG_CACHE_HOME/tui-music-player/library.sqlite3`。

当对应 XDG 基础目录变量未设置时，使用规范默认值，例如 `~/.config`、`~/.local/share` 和 `~/.cache`。程序不会在音乐目录中写入索引、配置或播放列表。

### 4.2 音乐库数据模型

当前的 `Vec<PathBuf>` 改为明确的曲目模型。核心字段计划包括：

```text
Track
├── canonical_path
├── relative_path
├── title
├── artist
├── album
├── duration
├── format_or_codec
├── file_size
└── modified_time
```

界面显示优先使用标签标题；没有标题标签时退回文件名。歌手和专辑缺失时显示为空或“未知”，不会阻止播放。

### 4.3 后台扫描和 SQLite 索引

扫描和媒体信息读取在单独的库工作线程中进行，主线程继续处理按键和绘制界面。线程通过消息通道发送：

- 扫描开始和结束。
- 已扫描数量及发现曲目数量。
- 新增、更新、删除的曲目。
- 可恢复警告和严重错误。

索引以规范化绝对路径为主键，使用文件大小和修改时间判断是否需要重新读取元数据。重新扫描时：

1. 未变化文件直接使用 SQLite 缓存。
2. 新文件或发生变化的文件通过 GStreamer Discoverer 读取元数据。
3. 当前扫描根目录中已经不存在的文件从缓存索引移除。
4. 播放列表中的对应路径不删除，只标记为不可用。

不跟随目录符号链接，避免目录循环和越界扫描。遇到无权限目录或损坏音频时继续扫描，并在状态区域汇总警告。

SQLite 使用系统库，不启用把 SQLite 源码静态打进程序的 `bundled` 特性。数据库通过 `PRAGMA user_version` 管理模式版本。缓存文件损坏或版本无法迁移时，程序先保留错误信息，再允许安全重建索引；不会触碰播放列表或音乐文件。

### 4.4 GStreamer 播放后端

使用 GStreamer 的高级播放接口替换 `ffplay`、`libc::kill` 和子进程管理。播放器负责：

- 加载本地文件 URI。
- 播放、暂停和停止。
- 获取当前位置和总时长。
- 跳转到指定位置。
- 设置 0% 至 100% 音量和静音。
- 接收播放结束、错误和状态变化事件。
- 禁用视频输出，避免带封面或视频流的文件弹出窗口。

GStreamer 消息转换成应用内部事件，由 TUI 主循环统一更新状态。播放错误显示实际原因，并自动跳过队列或播放序列中无法打开的曲目，防止在同一坏文件上无限循环。

### 4.5 播放顺序、队列和历史

播放模式：

- `Sequential`：顺序播放，到末尾停止。
- `RepeatAll`：到末尾回到第一首。
- `RepeatOne`：没有手动队列时重复当前歌曲。
- `Shuffle`：随机选择，曲库有多首时避免立即重复同一首。

优先级规则：

1. 当前曲目播放结束或用户按下一曲时，先消费手动队列头部。
2. 队列为空后才应用当前播放模式。
3. 按 Enter 立即播放其他歌曲时，不清空手动队列。
4. 上一曲使用实际播放历史，不重新猜测随机顺序。
5. 不可用队列项被跳过并显示提示。

队列只存在于当前运行中，退出程序后清空。

### 4.6 搜索

使用高层 `nucleo` 工作器在后台匹配，避免大型曲库输入搜索词时阻塞界面。匹配范围：

- 标题。
- 歌手。
- 专辑。
- 相对路径。

搜索忽略拉丁字母大小写并启用合理的 Unicode 规范化。结果按匹配得分排序；同分时保持音乐库原有稳定顺序。搜索只改变可见列表，不改变队列、播放列表、曲库索引或当前播放。

### 4.7 配置

`config.toml` 至少包含：

- 配置格式版本。
- 主音乐库目录。
- 音量。
- 静音状态。
- 播放模式。

首次启动时使用 XDG Music 目录。位置参数是会话覆盖，不写入配置。另提供明确的 `--set-library PATH` 用于永久设置主库。

配置使用临时文件加原子重命名写入，避免程序中断产生半个 TOML 文件。配置解析错误不会静默覆盖原文件，而会报告路径和原因并使用安全默认值启动。

### 4.8 命名播放列表

每个播放列表是独立、带格式版本的 JSON 文件，内容至少包含实际显示名称和曲目路径列表。文件名使用安全编码，防止播放列表名称产生路径穿越或覆盖其他文件。

计划行为：

- 创建前校验非空名称和名称冲突。
- 将当前选中曲目加入指定播放列表。
- 查看列表内容并从列表开始播放。
- 从播放列表移除项目只修改 JSON，不删除音乐。
- 删除播放列表前要求确认。
- 所有写入使用临时文件和原子重命名。
- JSON 损坏时报告具体文件并跳过，不自动覆盖。

### 4.9 命令行接口

使用 `clap` 提供：

```text
music-player [DIRECTORY]
music-player --set-library PATH
music-player --help
music-player --version
```

启动终端原始模式之前完成参数、目录和 GStreamer 初始化校验，使错误能以普通终端文本输出。不存在、不是目录或不可读取的路径都返回非零退出码和明确原因。

### 4.10 界面与按键

基础快捷键：

| 按键 | 行为 |
|---|---|
| `↑/↓`、`j/k` | 选择歌曲 |
| `Enter` | 立即播放选中歌曲 |
| `Space` | 暂停/继续 |
| `←/→`、`h/l` | 后退/前进 10 秒 |
| `-`、`=` | 音量降低/提高 5% |
| `m` | 静音 |
| `n/p` | 下一首/上一首 |
| `z` | 切换播放模式 |
| `/` | 进入搜索输入 |
| `r` | 后台重新扫描 |
| `a` | 添加到队列末尾 |
| `A` | 添加为下一首 |
| `P` | 打开/关闭播放列表面板 |
| `?` | 打开/关闭完整帮助 |
| `q` | 退出 |

模式相关规则：

- 搜索输入状态下，普通字符写入搜索框，不触发全局快捷键。
- 搜索中 `Backspace` 删除字符，`Esc` 清除搜索并返回列表，`Enter` 播放当前结果。
- 帮助、播放列表、确认框等模态界面优先处理 `Esc`，不会直接退出程序。
- 播放列表面板提供创建、删除、查看、移除和开始播放操作；具体按键全部显示在面板底部和 `?` 帮助中。
- 窄终端下优先保留曲目列表和播放状态，队列/播放列表改为弹层，避免布局溢出。

正在播放区域增加：

- `当前位置 / 总时长`。
- 进度条。
- 音量或静音状态。
- 当前播放模式。
- 队列剩余数量。

### 4.11 依赖变化

计划新增的直接 Rust 依赖及用途：

| 依赖 | 用途 |
|---|---|
| `gstreamer` | GStreamer 核心和消息类型 |
| `gstreamer-play` | 高级播放控制 |
| `gstreamer-pbutils` | 媒体发现、时长和标签 |
| `clap` | 命令行解析、帮助和版本 |
| `dirs` | XDG Music 和基础目录 |
| `rusqlite` | SQLite 增量索引 |
| `serde` | 配置和播放列表序列化模型 |
| `serde_json` | 播放列表 JSON |
| `toml` | 配置文件 |
| `nucleo` | 后台实时模糊匹配 |

计划新增 `tempfile` 作为开发依赖，用于不污染真实 XDG 目录的测试。

计划移除：

- `libc`：不再发送 Unix 进程信号。
- `/usr/bin/ffplay` 运行依赖：不再启动 FFmpeg 子进程。

实现时选择与 Rust 1.97 和 Fedora 44 系统库兼容的稳定版本，并把确切版本锁入 `Cargo.lock`。所有直接依赖都记录到 `changelog.md`。

## 8. 当前假设和助手决定的低影响细节

- 音量默认 100%，每次调整 5%。
- 快进和快退步长为 10 秒，并限制在 0 到歌曲总时长之间。
- 默认播放模式为顺序播放。
- 曲目原始排序使用相对路径的稳定、忽略大小写排序。
- 搜索同分时保持原始曲库顺序。
- 扫描不跟随目录符号链接。
- 手动刷新使用 `r`，0.2.0 不加入文件系统实时监听。
- 配置、播放列表和缓存只写入用户 XDG 目录，不写入音乐文件或音乐目录。
- 0.1.0 没有持久数据，因此不需要旧配置迁移；RPM 文件升级即可。
- 不自动创建、提交、推送 Git commit 或 Git tag，除非用户明确要求。

这些细节可以在批准计划前调整。
