## 2. WP1 — 播放模式与键位

### 2.1 类型

`src/track.rs`：删除对外的四态 `PlayMode::next()` 作为产品 API。改为：

```rust
#[derive(Debug, Default, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum RepeatMode {
    #[default]
    None,
    All,
    One,
}

#[derive(Debug, Default, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct PlaybackMode {
    pub repeat: RepeatMode,
    pub shuffle: bool,
}
```

保留只用于读旧配置的 `PlayMode` 四态，或在 `config.rs` 里用一个私有 enum 反序列化后丢掉。

标签：

| Repeat | 文案 |
| --- | --- |
| None | 顺序 |
| All | 列表循环 |
| One | 单曲循环 |

Shuffle 开：在文案后加 ` · 随机`（例如 `列表循环 · 随机`）。

`z`：`None → All → One → None`，**不**动 shuffle。
`s`：toggle shuffle，**不**动 repeat。

### 2.2 配置

`src/config.rs` `AppConfig`：

```toml
# 新文件写入
repeat = "none"   # none | all | one
shuffle = false

# 仍能读（读完不再写回这个键）
play_mode = "sequential" | "repeat_all" | "repeat_one" | "shuffle"
```

迁移：

| 旧 `play_mode` | repeat | shuffle |
| --- | --- | --- |
| sequential | None | false |
| repeat_all | All | false |
| repeat_one | One | false |
| shuffle | None | true |

两套字段同时存在时，**新字段优先**。缺省与今天相同：顺序、不随机。

`CONFIG_VERSION` 保持 `1`。

**不要**把 `repeat`/`shuffle` 直接加到带 `#[serde(default)]` 的 `AppConfig` 上。
缺字段会被填成 `None/false`，无法和「用户真的写了顺序、不随机」区分，旧
`play_mode = "shuffle"` 会丢。用中间结构：

```rust
struct RawConfig {
    version: u32,
    // …
    repeat: Option<RepeatMode>,
    shuffle: Option<bool>,
    play_mode: Option<LegacyPlayMode>,
}
```

解析后再合并：新字段**只要出现一个就以新字段为准**（缺的那个用默认）；
两个新字段都缺则迁移 `play_mode`；再都缺则 Sequential。保存只写新格式。

补测试：旧 `play_mode = "shuffle"` 载入为 `repeat=None, shuffle=true`；
只有 `repeat = "all"` 的文件不回落到旧字段；保存后再读没有 `play_mode`。

### 2.3 UI / 帮助 / 手册

- `src/ui.rs` 右上角：`play_mode.label()` 改为 Repeat + 可选「随机」。右栏现在 `Length(30)`，最长「单曲循环 · 随机 · 音量 100% · 队列 N」会挤。改为更短右栏文案，或把右栏加到约 36–40。以不截断中文为准。

- footer / now-playing 不要再出现「播放模式」四态轮转字样。

### 2.4 测试

- 更新 `config.rs` 往返测试
- 更新 `app.rs` 里所有 `PlayMode::…` 赋值
- 新增：`z` 只改 repeat；`s` 只改 shuffle

## 3. WP2 — Shuffle bag

放在 `App`，不要放进 `Player`。

```text
original: 曲库下标 0..n（或稳定 path 列表）
bag: 本轮 permutation（Vec<usize>）
cursor: 下一首在 bag 中的位置
```

规则：

1. 打开 shuffle 或曲库变更且 shuffle 开：生成新袋。当前正在播的曲放在袋首（与 spotify-player 相同），其余 Fisher-Yates。cursor 指向袋中下一首（当前曲之后）。
2. **任何不是「从袋里消费下一首」的切歌都要重新锚定袋**：Enter 播另一首、从播放列表开始、`play_or_resume` 在无当前曲时播 selected。新 current 为袋首。
3. 自然结束 / 用户 Next（队列为空时）从袋里取下一首。**临时 queue 插播不消费袋、也不重建袋。**
4. 袋尽：
   - Repeat=None → `stop`，清 `playing_index`（与今天 Sequential 播完一致）
   - Repeat=All → **重洗一整袋**，再取第一首。新袋尽量不要以刚播完的那首开头（n>1）
   - Repeat=One 自然结束 → 不取袋，重播当前
5. 用户在 Repeat=One 下按 Next → 消耗袋（或袋尽则按 4）
6. Previous **不**在袋里倒退，只弹 history；从 history 回来也算「非袋消费」，按第 2 条重建袋
7. 关掉 shuffle：丢掉袋；之后 Next 按曲库顺序（当前 index+1，Repeat 决定是否绕回）

`next_library_index` 按二维模式重写。现有 `playback_modes_choose_expected_library_index` 拆成 Repeat 用例 + bag 用例。

补测：

- 袋内不重复，长度 = 曲库（当前曲在袋首时本轮其余各一次）
- 袋尽 + Repeat=None 停止
- 袋尽 + Repeat=All 得到新 permutation（与上一轮不完全相同的概率；测「会再生成」而不是「绕回同一袋」）
- Repeat=One 自然结束不前进
- Repeat=One + 用户 Next 前进
- Enter / 播放列表 / history Previous 之后，袋以新 current 为袋首
- 队列插播不重建袋

## 4. WP3 — Player / App 控制面

### 4.1 Player（`src/player/backend.rs`）

现有 `toggle_pause` 留给键盘空格，但 **Stopped 时它是空操作**
（`src/player/backend.rs`）。键盘空格可继续用它；**MPRIS PlayPause / 媒体
`Toggle` 在 Stopped 时必须走 `play_or_resume()`**，不能调 `toggle_pause()`。

Rodio 0.22.2 事实（`Temp/vendor-rodio/rodio-0.22.2/src/player.rs`）：

- `Controls.pause` 初值为 `false`（播放态）
- `append()` 在 `stopped==true` 时会把 `stopped` 清回 `false`
- `append()` 里 `.pausable(false)`，暂停靠之后的 `periodic_access` 写入
- 因此「append 后不调用 `play()`」**仍会出声**

正确做法：抽内部 `load(path, target: Playing | Paused)`：

```text
1. 解码
2. 先 backend.pause()（目标 Paused）或保持将要 play 的意图
3. 再 stop/clear + append
4. 目标 Playing 才 backend.play()；目标 Paused 保持 pause
```

`periodic_access` 的 `samples_until_update` 初值是 1，第一个采样前会先跑
modifier。只要 **append 之前** `pause==true`，第一帧就是静音，不会闪声。

对外：

```rust
pub fn play(&mut self, path: &Path) -> Result<(), String>   // load(..., Playing)
pub fn open(&mut self, path: &Path) -> Result<(), String>  // load(..., Paused)
pub fn pause(&mut self)
pub fn resume(&mut self)
pub fn seek_to(&self, pos: Duration) -> bool  // 成功才 true；内部仍 clamp
```

键盘相对 seek 用 `i64` 微秒或秒算目标，再 `seek_to`。媒体相对 seek 见 WP4。

`PlayerEvent::StateChanged` 继续可以不发。Seek 成功要有确认：`seek_to`
返回 `bool`，App 成功后发 `MediaEvent::Seeked { position }`（或递增
`seek_serial`），媒体线程只在确认后发 MPRIS `Seeked`。

测试（`tests/player.rs`）：

- `pause` 后 `position` 不变，`resume` 后续播
- `seek_to` 落到 clamp 后的位置（含亚秒）；失败/未播放返回 false
- `open` 后 state=Paused、position=0、**无声**（headless 泵也不推进可听 PCM）

### 4.2 App 行为

从 `handle_key` 抽出，键盘和媒体共用：

```text
play_or_resume()     // Stopped：current 否则 selected；Paused：resume；Playing：no-op
                     // Toggle / MPRIS PlayPause 一律走这里，禁止 toggle_pause()
pause()
stop_from_user()     // 媒体 Stop：等价 pause（若已停则 no-op）
play_next(natural)
play_previous()      // history
seek_rel_micros(i64) // 负值后退；越过曲尾 = Next
seek_to_requested(Duration, Option<TrackId>)
                     // SetPosition：TrackId 不符 / 位置 <0 / 超出曲长 → 忽略，不 clamp
                     // 成功才发 Seeked
set_volume           // >0 则 unmute
set_repeat / toggle_shuffle
```

切歌：

```text
was_playing = state == Playing
装新曲：was_playing 则 play()，否则 open()
history 规则不变
```

顺序模式最后一首自然结束：仍走内部 `Player::stop()` + `playing_index = None`，对外以后是真正的 Stopped。这不是用户 Stop。

Stopped 时系统/键盘 Play：`play_or_resume` 按 §0。

### 4.3 测试

- Paused 时 `play_next`：新曲 `Paused`，position=0
- Playing 时 `play_next`：新曲 `Playing`
- `play_or_resume` 在 Paused 不重头
- Stopped 无当前曲时播 selected
- 媒体 Stop 后 state 仍 Paused、position 不变

用 `App::new_for_tests` + 现有测试媒体，不要打开声卡。

## 5. WP4 — MediaSession + Linux MPRIS

### 5.1 模块

```text
src/media/mod.rs       MediaCommand / MediaSnapshot / MediaSession
src/media/linux.rs     #[cfg(target_os = "linux")]
src/media/windows.rs   #[cfg(target_os = "windows")]
src/lib.rs             pub mod media;
```

`main.rs` 在 `App::new` **之后** `MediaSession::start()`。
`App::new` / `new_for_tests` **不**启动会话。

`start()` **不能** `spawn` 完就当成功。worker 先做完 D-Bus 注册 /
`GetForWindow`，再通过一次性 channel 回报 `Ready` 或 `Err`；`start()`
等这次握手再返回。`MediaSession` 持有 shutdown sender + `JoinHandle`；
`Drop`：发 shutdown → 停 Linux server / 拆 SMTC handler → 毁 HWND →
`RoUninitialize` → `join`。

Windows 线程：先 `RoInitialize`（或 windows-rs 对应封装），再创建窗口和
WinRT 对象；退出配对反初始化。微软要求与 WinRT 交互的线程先初始化 Runtime。

```text
MediaCommand:
  Play, Pause, Toggle, Next, Previous,
  SeekRelMicros(i64), SeekTo { position: Duration, track_id: Option<…> },
  SetVolume(u8),
  SetRepeat(RepeatMode), SetShuffle(bool),
  Quit
  // Stop 不进枚举：Linux 适配器在线程内改写成 Pause
  // Raise / OpenUri 丢弃
  // Toggle → App.play_or_resume()，Stopped 也会开播
```

`MediaSnapshot`：status、title/artist/album、path、duration、position、volume、muted、repeat、shuffle、can_go_prev（history 非空）、can_go_next（袋/顺序/队列判断）、track_id。

`MediaEvent`（App → 会话，不只靠 snapshot）：

```text
Seeked { position: Duration }   // 仅 seek_to 成功
```

主循环：

```text
drain MediaCommand → App
on_tick
publish snapshot（状态/曲目/音量/模式变化）
drain MediaEvent::Seeked → MPRIS Seeked / SMTC timeline
Windows：另按 500ms–1s 推 timeline
```

Seek 协议（在 App，不在 Player clamp 里混）：

| 来源 | 非法 / 越界 |
| --- | --- |
| MPRIS `Seek` 有符号微秒 | 加到当前位置；**越过曲尾 = Next**；落到开头之前则 0 |
| MPRIS `SetPosition` | TrackId 不符、位置 <0、超出曲长 → **忽略**，不 `seek_to` |
| SMTC 进度条 | 同 SetPosition（无 TrackId 则只检查范围） |
| SMTC FF/Rewind | `SeekRelMicros(±10_000_000)` |

### 5.2 Linux（`mpris-server` 0.10）

- 总线名：`org.mpris.MediaPlayer2.music_player`；冲突则 `…instance<pid>`
- `Identity = "Music Player"`，`DesktopEntry = "music-player"`
- `CanRaise = false`，`HasTrackList = false`，URI/MIME 空
- `CanQuit = true` → `Quit` → `should_quit`
- Player 方法按 §0 映射
- `Stop()` 在适配器里变成 `Pause`，**不要**把 PlaybackStatus 设成 Stopped
- `Seek` / `SetPosition` 按上一节协议拆开，不要都丢给 `seek_to` clamp
- `Volume` 0.0–1.0 ↔ 0–100；写入 >0 取消 mute
- `LoopStatus` / `Shuffle` 可写，映射 `RepeatMode` + `shuffle`
- Rate / Min / Max = 1.0
- Position：只读，从快照读微秒
- **仅** `MediaEvent::Seeked` 后发 MPRIS `Seeked`
- Metadata：`xesam:title/artist/album`，`mpris:length`，`mpris:trackid`，`xesam:url`（`file://`）。无 `mpris:artUrl`
- 曲目变了才推 Metadata（dirty-check）
- **不要**引入 tokio。实现 `Send+Sync`（channel + 快照）时优先 `Server`；
  只有实现不能跨线程才用 `LocalServer`。独立线程里用轻量非-tokio executor
  （如 `pollster` 或 `async-io` 的 `block_on`）驱动 `Server::new` 和信号。
- 注册失败经启动握手返回 `Err`，main 降级

Cargo：

```toml
[target.'cfg(target_os = "linux")'.dependencies]
mpris-server = "0.10"
```

不要默认 feature 里加 tokio。

容器验收（有宿主机 session bus 时）：

```text
playerctl -p music_player status
playerctl -p music_player play-pause
playerctl -p music_player next
playerctl -p music_player previous
playerctl -p music_player position 30
playerctl -p music_player volume 0.4
playerctl -p music_player loop Playlist
playerctl -p music_player shuffle On
playerctl -p music_player metadata
playerctl -p music_player stop    # 应变为 Paused，进度仍在
```

无 bus 的 CI 不跑上述命令。可加单测：命令枚举映射、Stop 适配成 Pause、旧配置迁移。不要在 unit test 里 `Server::new`。

## 6. WP5 — Windows SMTC

独立线程：

```text
RoInitialize（STA / windows-rs 对应封装）
注册窗口类
CreateWindowExW(
  WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW,
  WS_POPUP,
  0×0,
  父窗口 None        // 顶层，不是 HWND_MESSAGE
)
ISystemMediaTransportControlsInterop::GetForWindow
SetIsEnabled(true)
Play/Pause/Next/Previous/FF/Rewind = true
IsStopEnabled = false
DisplayUpdater Music
AutoRepeatMode / ShuffleEnabled 可写
ButtonPressed / PlaybackPositionChangeRequested /
  AutoRepeatModeChangeRequested / ShuffleEnabledChangeRequested
消息循环（Peek/GetMessage）直到 App 退出
DestroyWindow
```

对照 spotify-player：学 0×0 顶层窗 + 泵消息；**不要**主线程 winit。样式补上不激活、不进任务栏。

映射：

| SMTC | 命令 |
| --- | --- |
| Play / Pause | Play / Pause |
| Next / Previous | Next / Previous |
| FastForward / Rewind | SeekRel(±10s) 仅媒体键；进度条拖动走 SetPosition |
| PlaybackPositionChangeRequested | SeekTo |
| AutoRepeatMode | SetRepeat |
| ShuffleEnabled | SetShuffle |
| Stop | 不启用 |

`set_playback` + timeline：Playing/Paused/Stopped + Position/Start/End。播放中 0.5–1s 更新 Position。切歌更新 Title/Artist/AlbumTitle/时长。无 Thumbnail。

失败（无交互会话、GetForWindow 失败）：降级，测试不调用 `start()`。

Cargo：

```toml
[target.'cfg(target_os = "windows")'.dependencies]
windows = { version = "0.62.2", features = [
  "Foundation",
  "Media",
  "Win32_Foundation",
  "Win32_Graphics_Gdi",
  "Win32_System_WinRT",
  "Win32_System_LibraryLoader",
  "Win32_UI_WindowsAndMessaging",
] }
```

`Win32_Graphics_Gdi` 不能省：`WNDCLASSW.hbrBackground` 是 `HBRUSH`，被该
feature 门控。容器内 `cargo check --target x86_64-pc-windows-msvc` 用原 7
个 feature 会在 `RegisterClassW` / `WNDCLASSW` 上报 `E0432`；补上后
RoInitialize → 建窗 → `GetForWindow` 骨架可通过。souvlaki 0.62 也是 SMTC
本体一套 feature、自己建窗再加 Gdi（放在 dev-dependencies）。

真机验收（你这边 Win 构建已通）：锁屏 / `Win+A` / 媒体键 / 任务栏；Stop 按钮不出现；拖动进度；Repeat/Shuffle 若系统 UI 画出按钮则可改（画不出不算缺陷）。

smoke** 加进普通 CI（可复用 release 的 `fedora:44` + `./packaging/build-rpm.sh`），
避免 `mpris-server`/zbus 第一次完整打 RPM 发生在打 tag 之后。

## 9. 测试与验收矩阵

| 项 | 方式 |
| --- | --- |
| 配置迁移、键位、bag、Paused 切歌、seek_to、Stop→Pause | `cargo test --all-targets --locked`（`dev-fedora`） |
| fmt/clippy | 容器内，不要扫 `Temp/` |
| Linux 媒体键 / playerctl | 容器或宿主机，有 session bus |
| Windows SMTC | 真机 |
| CI linux+windows Test | 必须绿；无 bus / 无 HWND 不能失败 |
| CI Fedora RPM smoke | 普通 PR/push 跑 `build-rpm.sh`，不只 Release |
| 顺序最后一首 EOS | 仍停止，不是「假 Pause」 |
| 键盘 `p` 与系统 Previous | 同一条 history |
| `z` / `s` 与系统 Loop/Shuffle | 同一份 `PlaybackMode` |

## 10. 风险

| 风险 | 处理 |
| --- | --- |
| 无 session bus / GetForWindow 失败 | `start()` 失败降级 |
| Paused `play()` 闪声 | 只用 `open()`，禁止 play+pause |
| 右上角文案超宽 | WP1 一起改布局 |
| `CONFIG_VERSION` 误加 | 禁止；用字段迁移 |
| mpris-server 拉进 tokio | Cargo.toml 盯 feature |
| Windows 窗口进任务栏 / 抢焦点 | `WS_EX_NOACTIVATE \| TOOLWINDOW`，无 winit |
| 第二实例抢总线名 | `instance<pid>` |
| bag 与 history 纠缠 | Previous 不改 bag；只测「不倒退袋」 |
