# 默认主题白色系修正计划

状态：已批准并实施
范围：默认 TUI 颜色值修正，不改变布局和功能

## 1. 修正原因

上一版把主要前景色设为 `Color::Reset`。它的实际含义是恢复终端默认前景色，而不是固定白色；用户当前终端的默认前景色本身偏灰，因此界面视觉变化不明显。

本轮改为固定 RGB 白色层级，让播放器在深色终端中呈现稳定、干净的无彩色界面，同时继续遵守“不绘制全局背景”的设计边界。

## 2. 用户决定

1. 使用固定柔和白色层级，不再依赖终端 ANSI 白色映射。
2. 音频频谱也改为灰白渐变，默认界面不再持续显示青紫色。
3. 文件失效等异常继续保留红色。
4. 沿用此前确认的选中行深色背景 `#343846`。

## 3. 颜色系统

| 职责 | 新颜色 | 用途 |
|---|---|---|
| `primary` | `#F2F2F2` | 标题、曲名、播放操作、进度和搜索输入 |
| `muted` | `#B8B8B8` | 路径、歌手、专辑、时长、帮助和空状态 |
| `border` | `#8A8A8A` | 普通边框与分隔线 |
| `selection_bg` | `#343846` | 选中行局部背景，保持不变 |
| `danger` | `Color::Red` | 文件失效等异常，保持不变 |
| `spectrum_low` | `#A8A8A8` | 频谱低频端 |
| `spectrum_high` | `#F2F2F2` | 频谱高频端 |

界面仍然没有全局背景色字段，也不会设置终端背景。

## 4. 实施步骤

1. 修改 `src/theme.rs` 中唯一默认主题的颜色值。
2. 更新主题和频谱端点单元测试；不修改 `src/ui.rs` 的渲染结构或业务行为。
3. 更新 `README.md`、`assets/brand-spec.md` 和 `changelog.md`，说明 TUI 已改为灰白频谱；正式 Logo 的青紫品牌渐变保持不变。
4. 运行格式化、Clippy、完整测试及差异检查。

## 5. 验收标准

1. 主文字明显呈现柔和白色，而不是终端默认灰色。
2. 次要文字和边框仍有清楚但克制的亮度层级。
3. 频谱只使用灰白渐变，不再出现青色和洋红色。
4. 选中行深色背景和红色异常提示保持正常。
5. 应用不绘制全局背景，也不新增依赖、配置项或主题切换。
6. 自动测试全部通过，并由用户在当前终端中人工确认效果。

## 6. 技术细节与假设

- 本轮只替换集中主题中的颜色值，因此改动范围很小，不需要调整 UI 控制流。
- 固定 RGB 会让白色层级在不同真彩色终端中更一致，但不再跟随用户的前景色配置。
- 假设运行环境支持真彩色；不支持真彩色的终端可能自行近似这些颜色。
- Logo 用于品牌识别，继续保留正式批准的青紫渐变；TUI 用于长时间观看，采用灰白显示色。

## 7. 推迟决定

- 多主题切换。
- 浅色终端专用主题。
- 根据终端背景自动选择颜色。
- 修改正式 Logo 配色。
