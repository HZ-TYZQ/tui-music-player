# 默认主题收敛实施计划

状态：已批准并实施
范围：默认 TUI 配色与样式集中管理
版本策略：本轮不修改版本号，不新增主题切换

## 1. 目标

把当前同时使用青、洋红、黄、绿等多种强调色的默认界面，收敛为尊重终端主题的简约单色界面。

完成后应满足：

- 播放器不绘制、不覆盖全局终端背景。
- 主要文字继承用户终端的默认前景色。
- 次要信息和普通边框使用终端提供的暗灰色层级。
- 选中行保留当前局部深灰背景。
- 播放、暂停等常规状态不再通过黄、绿等颜色区分。
- 文件丢失等异常仍可使用终端红色。
- 只有音频频谱保留多色渐变，并降低约 25% 饱和度。
- 配色由集中式 `Theme` 结构管理，但本轮不增加用户配置或主题切换。

## 2. 已确认的设计边界

### 2.1 用户决定

1. 全局背景必须继续来自终端主题，这是项目最初的设计边界。
2. 不接受播放器设置固定深色背景或绘制额外表面。
3. 保留当前选中行的局部深灰背景。
4. 频谱仍是唯一持续使用多色的界面区域，但饱和度降低约 25%。
5. 使用集中式 `Theme` 结构，为未来维护留出清晰入口；本轮只提供一个默认主题。

### 2.2 截图体现的目标气质

- 终端背景自然透出，没有应用自建的大色块。
- 边框、普通文字和元数据形成低对比度灰阶。
- 选中行是唯一常驻的局部背景强调。
- 界面适合长时间浏览和播放，不需要营销页面式的高刺激色彩。

用户提供的终端截图只作为本轮视觉参考，不复制到仓库；截图包含本机路径和真实歌曲信息，避免把个人环境信息纳入公共源码。

## 3. 当前问题

当前 `src/ui.rs` 同时把终端命名色用于多个普通界面元素：

- 青色：主标题、音频格式、选中箭头、进度条、频谱标题、搜索和多个弹窗边框。
- 洋红色：正在播放区域和播放列表详情边框。
- 黄色与绿色：播放和暂停操作图标。
- 红色：文件丢失警告。
- RGB 渐变：音频频谱。

其中只有文件丢失和频谱真正需要颜色承担信息。其他颜色属于装饰性强调，而且 ANSI 命名色会被不同终端主题映射为不同饱和度，使界面气质不可预测。

## 4. 设计系统

### 4.1 使用场景四问

- 叙事角色：长时间使用的本地音乐管理和播放工具，不是营销展示界面。
- 观看距离：普通桌面终端距离，信息密度高，需要稳定的层级而非大面积强调色。
- 视觉温度：安静、清爽、克制、原生终端感。
- 容量估算：标题、歌曲元数据、播放状态、频谱和页脚同时存在；颜色必须主动退后，避免多区域争夺注意力。

### 4.2 默认主题字段

计划新增 `src/theme.rs`，定义仅供当前 crate 使用的 `Theme` 和 `DEFAULT_THEME`：

| 职责 | 颜色 | 用途 |
|---|---|---|
| `primary` | `Color::Reset` | 主标题、主要文字、播放操作图标、进度条 |
| `muted` | `Color::DarkGray` | 路径、歌手、专辑、时长、帮助文字、空状态 |
| `border` | `Color::DarkGray` | 普通区域、播放区域、弹窗和分隔线 |
| `selection_bg` | `Color::Rgb(52, 56, 70)` / `#343846` | 保留当前选中行效果 |
| `danger` | `Color::Red` | 文件不可用等异常 |
| `spectrum_low` | `Color::Rgb(45, 188, 195)` / `#2DBCC3` | 降低饱和度后的低频端 |
| `spectrum_high` | `Color::Rgb(201, 89, 171)` / `#C959AB` | 降低饱和度后的高频端 |

`Theme` 不提供 `background` 字段，避免未来调用者无意间突破“不接管终端背景”的产品边界。

### 4.3 层级规则

- 主标题和当前曲目通过粗体强调，不使用彩色前景。
- 普通边框全部归一到 `border`。
- 选中箭头使用默认前景色，选中行继续使用 `selection_bg`。
- 播放中显示 `⏸`、暂停时显示 `▶`；两者使用同一主文字颜色，语义由图形而非黄/绿表达。
- 停止状态与次要信息使用 `muted`。
- 搜索输入通过粗体、光标和位置表达激活状态，不再使用青色。
- 频谱标题使用单色，只有频谱柱调用渐变。

## 5. 实施方案

### 阶段一：建立集中式主题

计划新增：

- `src/theme.rs`：定义 `Theme` 和唯一的 `DEFAULT_THEME`。

计划修改：

- `src/lib.rs`：将主题模块暴露给 crate 内部，不增加新的公共 API。
- `src/ui.rs`：从入口向绘制函数传递 `&Theme`，移除散落的颜色常量和命名强调色。

主题只负责颜色职责，不负责布局、文字、按键或应用状态。

### 阶段二：迁移界面元素

按执行顺序迁移：

1. 音乐库标题、元数据、选中箭头和选中背景。
2. 正在播放区域、进度条及播放/暂停图标。
3. 频谱标题和降低饱和度后的频谱端点。
4. 搜索、状态消息和页脚。
5. 播放列表、帮助、新建与删除确认弹窗。
6. 文件失效警告继续使用 `danger`。

不修改任何业务逻辑和键盘行为。

### 阶段三：同步文档

计划修改：

- `assets/brand-spec.md`：区分 Logo 使用的品牌主渐变和 TUI 使用的低饱和显示渐变；正式 Logo 本轮保持不变。
- `README.md`：说明默认界面继承终端背景，频谱是唯一的持续多色区域。
- `changelog.md`：记录默认主题收敛及没有新增依赖。

## 6. 测试与验证

### 6.1 聚焦测试

- 验证默认主题的主色为 `Color::Reset`，没有全局背景字段或背景绘制路径。
- 验证播放和暂停图标继续表达正确操作，并使用相同的主前景色。
- 验证停止状态使用次要色。
- 验证频谱首尾柱分别使用 `#2DBCC3` 和 `#C959AB`。
- 保留所有现有频谱、布局和播放状态测试。

### 6.2 自动验证

- `cargo fmt --all -- --check`
- `cargo clippy --all-targets --locked -- -D warnings`
- `cargo test --all-targets --locked`
- `git diff --check`

### 6.3 人工验证

- 在用户当前终端主题中启动播放器。
- 核查全局背景完全没有变化。
- 核查选中行保持截图中的局部深灰效果。
- 核查标题、边框、播放状态、搜索和弹窗不再出现装饰性青/洋红/黄/绿。
- 播放音乐并核查频谱仍有识别度，但比当前版本更柔和。

人工终端观感无法由单元测试完全证明，最终以用户截图和实际使用确认作为验收的一部分。

## 7. 当前假设

- 用户当前终端主题的默认前景色和 `DarkGray` 已经形成满意的对比层级。
- 局部选中背景 `#343846` 不属于被禁止的全局背景；用户已明确选择保留。
- 频谱降低饱和度只作用于 TUI，已经批准的正式 Logo 不修改。
- 红色只在异常出现时使用，不构成默认界面的多巴胺配色。
- 本轮不持久化主题名称，不改变配置文件版本。

## 8. 推迟决定

- 多主题切换和主题配置持久化。
- 浅色终端专用调色。
- 自动查询终端背景亮度。
- 修改正式 Logo 的渐变饱和度。

## 9. 验收标准

1. UI 没有设置全局背景色。
2. 除局部选中行外，不新增任何固定背景色。
3. 常规界面不再使用青、洋红、黄、绿作为装饰性强调。
4. 文件失效仍有明确异常提示。
5. 频谱使用降低饱和度后的渐变。
6. 全部自动测试通过。
7. 用户在自己的终端主题中确认视觉效果符合“简约清爽”。

## 10. 批准方式

用户明确批准本计划后进入实施。实现完成后先由用户在当前终端主题中人工核查，再决定暂存、提交或继续调整。
